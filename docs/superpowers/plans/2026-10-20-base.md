# Subprojeto 1 (Base) — Plano de implementação

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Entregar login, perfis e permissões, gestão de usuários, auditoria e o layout do admin do Natal Solidário, rodando nos emuladores e publicado no projeto Firebase de desenvolvimento.

**Architecture:** Monorepo npm com workspaces:
- `shared/`: matriz de permissões e tipos.
- `functions/`: Cloud Functions v2 callable, empacotadas com esbuild para embutir `shared`.
- `web/`: Next.js App Router com o portal em `/` e o admin em `/admin`, renderizado no cliente.

Regras do Firestore e do Storage em `firebase/`. A autorização sempre consulta `usuarios/{uid}` (`perfis` e `ativo`); os custom claims servem só de cache.

**Tech Stack:** Node 24, npm workspaces, TypeScript, Next.js (última estável), Tailwind CSS, shadcn/ui, Firebase JS SDK, firebase-admin, firebase-functions (v2), Zod, Vitest, @firebase/rules-unit-testing, Playwright, esbuild.

**Spec:** `docs/superpowers/specs/2026-10-20-base-design.md`

## Global Constraints

- Perfis exatos: `admin`, `diretoria`, `tesouraria`, `editor`, `almoxarifado`, `coord_voluntarios`, `membro`.
- Permissões da Base: `admin:acessar`, `usuarios:ver`, `usuarios:gerenciar`, `auditoria:ver`.
- Todos os perfis exceto `membro` têm `admin:acessar`. `usuarios:ver` e `auditoria:ver` ficam com `admin` e `diretoria`; `usuarios:gerenciar`, só com `admin`.
- Coleções: `usuarios/{uid}` e `auditoria/{id}`, com os campos exatamente como na spec, seção 4.3.
- Autorização (regras e Functions) lê `usuarios/{uid}` e exige `ativo == true`.
- Nenhum usuário é apagado. A coleção `auditoria` não aceita escrita de cliente.
- Textos da interface e mensagens de erro em português do Brasil. Datas exibidas em `America/Sao_Paulo`.
- Emuladores usam o projeto `demo-natal-solidario`, que roda sem projeto real.
- Nenhum segredo no repositório. A configuração vai em `web/.env.local` (no `.gitignore`), com `web/.env.example` como modelo.
- Commits terminam com `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **E-mail com maiúsculas ou espaços** (`" Ana@Exemplo.com "`): é normalizado para minúsculas, sem espaços, e um segundo convite para o mesmo endereço dá `already-exists`. Teste na Tarefa 4.
2. **Dois admins removendo o perfil um do outro ao mesmo tempo:** a contagem de admins ativos acontece dentro de uma transação, e o sistema nunca fica sem admin ativo. Teste na Tarefa 5.
3. **Usuário desativado com token ainda válido:** a próxima leitura no Firestore e a próxima chamada a Function são recusadas. Testes nas Tarefas 3 e 5.
4. **Usuário tentando promover a si mesmo** gravando `perfis` ou `ativo` no próprio documento: as regras negam. Teste na Tarefa 3.
5. **Entradas fora do formato** (nome vazio ou com mais de 100 caracteres, telefone com letras, lista de perfis vazia ou com perfil inexistente): `invalid-argument`, com mensagem em português. Teste na Tarefa 4.
